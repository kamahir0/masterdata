# 関数カラムとテーブル書式のGrid評価

Status: Implemented

2026-11-11 Human Requirement。分割された同一テーブルの全レコードを使って表示値・書式を計算する。独自DSLを作らない。実行開始の契機はHumanが指定していない。以下のAPI、合成、診断、キャッシュ戦略はAgent Decision。[スキーマ編集](display-schema.md)と[言語選定](../adr/0002-display-runtime.md)を参照。

## 実行の境界と開始条件

BrowserとDesktopのGridにローカル同梱のQuickJSを遅延ロードする。専用WorkerでVMを動かし、表示中のテーブルの通常レコードの読み取り専用コピーだけを渡す。ゲストにホスト関数やハンドル、ファイル、通信、IPC、DOM、ストレージ、モジュールローダーを提供しない。CLI、保存、Build、Publishでは一切評価しない。

2026-11-11 Human decision basis「UXが良い方にする」。自動復元時にも初期の表が開くことと、セッションごとの手動有効化との違いを提示した後、選択を主担当へ委任された。表示定義のある表を表示したときに自動計算する。正本のYAML中に同名の任意キーがあっても実行対象にせず、専用の付随ファイルだけを評価する。定義のない表ではWorkerを起動しない。表を離れると処理を終了する。

## 関数APIとドロップ率

同期スクリプトの引数は `row`（現在の通常レコード）、`table`（同一表全件の `rows`、プリミティブ値で厳密一致を取る `group(field, value)` と `sumBy(groupField, groupValue, valueField)`）、`column`（`name` と `kind: "data" | "function"`）。他の計算列の結果を入力に含めず、循環を作らない。64bit整数はBigIntで渡す。型に合う整数フィールドの編集前後で引数の型を揃え、未入力や型不正を0に変換しない。

`sumBy` は同一グループの値がすべて整数ならBigIntで加算する。数値型の浮動小数は有限値を加算する。空・欠損・非数値・宣言型の範囲外（uintの負値など）・整数と浮動小数の不整合ではnullを返す。グループと集計は版ごとに索引化し、表示セルごとの全表走査を避ける。例のweightはuintとする。負値を含むプールは合計がnullになる。

```js
const total = table.sumBy("poolId", row.poolId, "weight");
if (row.poolId == null || typeof total !== "bigint" || total <= 0n) {
  return { text: "—" };
}
const hundredths = (row.weight * 10000n + total / 2n) / total;
return { text: Number(hundredths) / 100 + "%" };
```

## 表示と書式

- 関数列は通常列の後ろに定義順に並べ、見出しに関数であることを示す。各セルは `{text: string, style?: Style}` を返す。文字列はプレーンテキストとして描画する。テーブル書式は通常列・関数列を対象とし、`Style` または `null`（適用なし）を返す。管理用の行番号・配布タグ等は対象外。
- Styleには任意の `bold`、`italic`（boolean）、`color`、`backgroundColor`（#RRGGBB）を許す。関数列のスタイルを基礎とし、定義順にルールを重ね、各プロパティで最後の明示値を採用する。falseは先行するtrueを解除する。書式からtext等を返した場合はそのルールを診断し、元の表示と他の書式を保持する。背景色は入力やテキストの周囲の余白を含め、セルの四辺まで塗る。条件から外れたセルは通常の背景に戻る。選択・エラー・フォーカスが判別できること。
- 検索は実レコードを対象に維持する。検索、file絞り込み、profile、スクロールは集計母集団に影響しない。範囲コピーには関数列の表示テキストを含む。行の複製・レコードコピーは実データを対象とする。貼付けとDeleteは関数列で位置を消費して書込みをスキップし、関数列だけの操作で実レコードやUndo履歴を変更しない。範囲に計算待ちのセルがあればコピーを保留したことを知らせ、不完全な値でクリップボードを上書きしない。
- 編集・追加・削除・並替え・定義変更・Undo / Redoで対象表の世代を更新する。表示は版と行の同一性で管理し、遅れた結果で新しい表示や別行を上書きしない。スクロールで表示される行を優先し、キャッシュと処理キューを有界にする。
- 失敗した関数列のセルには計算エラー、書式失敗では既存表示と対象ルールの診断を示す。定義名・原因・修正入口が分かる。構文・戻り値・例外・制限超過を区別し、修正・Undoで再計算できる。表示の失敗で通常編集・Save・Buildを止めない。
- VMのヒープ・スタック、評価時間、入力スクリプト・出力テキスト・診断の長さ、キューを制限する。VMの割込に応答しない処理は外側からWorkerを終了する。異常終了した同じ定義を自動リトライし続けない。失敗したコードが次の定義のグローバルや組込みを書き換えた状態を残さない。

## 評価範囲の上限

テーブル当たり10万行、表示先256列、関数・書式合わせて32定義までとする。1定義のコードは32,768文字、セル本文は4,096文字まで。表データと定義の転送・VM入力にもサイズ上限を設ける。各定義に独立したコンテキストを割り当て、合計のゲストヒープ予算を48MiB、個別は24MiB以下とする。範囲コピーは計算結果を含む場合に限り2048行と結果キャッシュの容量を上限とし、超過時は小さい範囲を選ぶよう案内する。

## 受入と検証

- 同一プールに2ファイルで20、30、50を配置し、別プールを加える。一つのfile・検索結果・profile・仮想viewportから20%、30%、50%の母数を確認する。編集、プール移動、追加、削除、並替え、Undo / Redo、再読込の各結果を照合する。
- 0合計、負値、欠損・不正型、ulong最大値、複数書式（競合・false・異なる属性）、構文不正、throw、不正な戻り値、無限ループ、メモリ上限と正常な定義への回復を確認する。
- 生データのみのプロジェクトの追加読込がないこと、1万行の分割テーブルで索引作成回数・表示範囲の評価数・再編集時の応答を測定する。Chromium・WebKitとproduction CSPでローカル実行し、ホスト権限が提供されないこと、表切替・閉じた後の処理終了を確認する。
- Browser / Desktopの選択・コピー・貼付け・入力・保存を通し、CLIと生成C#・MasterMemoryには実データだけが入ることを確認する。

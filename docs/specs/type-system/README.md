# Type-system specifications

Type-system rules are split into independently reviewable canonical documents so Primitive, Value Object, Enum/Flags, and Custom Type behavior can progress through Draft, Proposed, Approved, and Implemented without sharing one document-wide status.

- [Primitives](primitives.md)
- [Value objects](value-objects.md)
- [Enums and flags](enums.md)
- [Custom types](custom-types.md)

These files preserve the existing Requirement IDs. Splitting a document does not rename or reassign an ID.

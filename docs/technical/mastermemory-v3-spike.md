# MasterMemory v3 technical spike

Status: Experimental validation artifact

This spike is intentionally independent from the product YAML Type System and
from the production schema-driven generator. It proves only that the pinned
.NET dependency can be invoked through `masterdata-dotnet` and can perform the
MasterMemory v3 round trip:

```text
hand-written TestMaster.cs equivalent
  -> dotnet build/run
  -> MasterMemory Source Generator
  -> DatabaseBuilder.Build()
  -> binary file
  -> MemoryDatabase(byte[])
  -> generated FindBy... lookup/assertion
```

## Pinned inputs

- .NET SDK: repository `global.json` requires the 8.0.300 feature band and
  allows the latest feature roll-forward.
- MasterMemory NuGet: `3.0.4`.
- MessagePack NuGet: `3.1.3`.
- Target framework: `net8.0`.

The package versions are explicit because they are future builder cache
compatibility inputs. The technical spike has its own project at
`dotnet/spike/masterdata-mastermemory-spike.csproj`; it is not generated by the
Rust C# scaffold. Its `packages.lock.json` is checked in and locked restores
are enabled so transitive versions do not drift silently. The current pinned
MessagePack version produces NuGet audit warnings in this environment; the
spike keeps the version required by the selected MasterMemory package and a
future dependency upgrade must be evaluated as a compatibility/security
change rather than hidden by suppressing the warnings.

## What it verifies

The spike declares one hand-written `SpikeItem` table with an integer primary
key and three records. It builds a binary, writes it below `target/`, reloads
that binary into the generated `MemoryDatabase`, calls
`FindByItemId(1002)`, and asserts that the record is `Hi-Potion`. The Rust
`masterdata-dotnet` bridge parses the JSON result and exposes the evidence to
`cargo xtask mastermemory-spike` and `cargo xtask check-all`.

## Boundary and non-goals

The spike does not parse the repository YAML, generate production C#,
reimplement MasterMemory internals in Rust, or define the product's future
primary-key specification. A successful spike is compatibility evidence for
the .NET adapter only.

Run it with:

```text
cargo xtask mastermemory-spike
```

The command requires a network-capable .NET restore on a clean machine. CI
runs it after installing the .NET 8 SDK on Ubuntu, Windows, and macOS.
